# Intent

## Speaker notes

Agents write code faster than a person can read it.

Pablo's attention is the scarce resource, so the walkthrough spends it carefully.

He should finish the deck knowing what the feature does and how it is put together.

He should also know where he would look if he wanted to check a claim.

Most of the time he will not need to open the code at all.

So the subject of each slide is a logical thing: a component, a flow, a rule.

A walkthrough is not a tour of files. File coverage is only a backstop.

It is not a sales pitch. A deck that hides a weak spot has failed.

It is not an approval. Pablo's commit approves; the deck only informs it.
