# Use cases

## Speaker notes

The first reader is Pablo, deciding whether a sprint can be accepted.

He reads slides one to five for the why, then the diagrams for the how.

He reads component slides next, and clicks fine print only where a claim surprises him.

The second reader is an independent reviewer.

For that reader every claim must be checkable: a test, a log, a line of code.

The third reader is the implementing agent itself, before it starts.

The fourth reader arrives weeks later and needs the feature explained once, well.

The last use is presenting. Each slide must work on a screen while someone talks.

That is why the visual is separate from the notes.

If a slide only makes sense after reading its notes, the visual is too weak.
