# How to check a walkthrough

## Speaker notes

This is the walkthrough's own "how to test" slide.

In a real walkthrough, slide four explains how to test the feature instead.

A walkthrough must first pass every check that any presentation must pass.

Those are defined once, in Presentations, and are not repeated here.

The checks on this slide are the ones only a walkthrough needs.

The implementing agent runs them before it stops for review.

The independent reviewer runs them again and does not trust the first result.

Element coverage needs judgement. The others are mechanical and belong in a small script beside the deck.

Numbers deserve the most care. A figure with no evidence file behind it is a claim, not a result.

A walkthrough names the commit or working tree it describes, because code moves faster than slides.

This folder passes its own checks. If it stops passing, fix the folder.
