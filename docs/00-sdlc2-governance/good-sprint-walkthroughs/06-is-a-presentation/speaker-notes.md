# A walkthrough is a presentation

## Speaker notes

"Presentation" is the parent word. "Walkthrough" is one type of presentation.

Everything about the form is inherited and lives in the Presentations rule.

That covers the slide unit, the 50-line budget, fine print, the index, the shared checks, and revisions.

This folder does not repeat those rules. One rule, one place.

What a walkthrough adds is a purpose and the content that purpose requires.

The purpose: Pablo understands an implemented sprint without rebuilding it from the code.

So it adds a fixed opening, the logical elements to cover, and patterns for explaining them.

It adds a closing that keeps the deck honest: results, weak spots, a runbook, an index.

And it adds a moment in the workflow: after implementation, before review.

In a walkthrough, fine print means three things: the source, the proving test, and the evidence.

Other types of presentation will add different content to the same form.

An agent asked for a presentation that is not a walkthrough does not add these slides.
