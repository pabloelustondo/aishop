# Lifecycle of a presentation

## Speaker notes

A presentation is a proposal until Pablo commits it, like any governed document.

The agent drafts it, checks it, and stops. It does not stage, commit, or push.

Pablo reads it in order and opens fine print only where he wants to check.

If he wants changes, the agent produces a new revision and says what moved.

A silent edit to a reviewed presentation is not allowed. He must be able to see the difference.

His commit approves the exact contents. It approves nothing the slides describe.

Presentations go stale, because code and plans move on.

A presentation states what it describes, so staleness can be noticed.

When it no longer matches, correct it or mark it stale at the top of its index.

If a generator is used, slide text and notes come from one source, or they will drift apart.
