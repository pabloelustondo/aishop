# Defining a new type

## Speaker notes

A type exists when Pablo has committed a rule for it. A name alone is not a type.

The rule is a folder in governance, built as a presentation.

It answers the six questions on the slide, and nothing the shared form already answers.

Do not repeat the slide unit, the line budget, or the shared checks in a type.

Link to this folder instead. One rule, one place.

A good type is built from a real case, the way the walkthrough came from a real sprint.

So write the first instance, learn what worked, and only then write the rule.

The type's folder demonstrates its own rule, using real examples with fine print.

A type may add required slides, required order, and checks. It may not relax the shared form.

Pablo names types. An agent may suggest one, with its reason, and then waits.
